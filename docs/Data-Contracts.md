# Data Contracts

> The single source of truth for every shape that crosses a boundary (cv → api → db → web). Change this file **before** changing code. Code lives in `packages/contracts/nigehban_contracts/` (Pydantic). Web TS types are generated from the API's OpenAPI schema and are never hand-written.

## 1. Conventions
- **JSON casing:** `snake_case` everywhere (Python, DB, API, generated TS).
- **IDs:** `<prefix>_<ULID>` (26 uppercase Crockford base32 characters), generated server-side except `evt_` (generated by cv so retries are idempotent). Each ID field accepts only its own prefix.

  | Prefix | Entity | | Prefix | Entity |
  |---|---|---|---|---|
  | `evt_` | DetectionEvent | | `run_` | Run |
  | `alt_` | Alert | | `cam_` | Camera |
  | `act_` | AlertAction | | `usr_` | User |

- **Human reference:** `ref_code` = `SEC-<YYYY>-<NNN>-<A|T>` (A = abandoned, T = theft), e.g. `SEC-2026-004-T`.
- **Time:** `occurred_at` and all `*_at` are UTC ISO-8601. `video_ts_s` is seconds from the start of the video. **Detection logic uses video time only, never wall-clock time.**
- **Boxes:** `bbox = [x1, y1, x2, y2]` in pixels of the source frame, with `x1 >= 0`, `y1 >= 0`, `x2 > x1`, `y2 > y1`.
- **Track IDs:** ByteTrack integers. They are unique **within one run only**. "Person #12" in the UI means `track_id 12` in that run.
- **Versioning:** every event carries `schema_version` (currently `1`).
- **Validation:** every contract model rejects unknown keys. Timestamps must be timezone-aware and are normalised to UTC. `video_ts_s >= 0`. Numbers and flags are strict: no booleans as numbers, no numeric strings, no `NaN` or infinity (JSON integers are fine where a float is expected).
- **Python naming:** `bag.class` is `class_` in Python (alias `class`). JSON and OpenAPI always say `class`.

## 2. Enums
| Enum | Values |
|---|---|
| `EventType` | `abandoned_bag`, `possible_theft` |
| `BagClass` | `handbag`, `backpack` |
| `EventSource` | `real`, `mock` |
| `AlertStatus` | `active`, `acknowledged`, `resolved`, `false_alarm`, `authorised_pickup`, `confirmed_theft` |
| `RunStatus` | `queued`, `running`, `completed`, `stopped`, `failed` |
| `UserRole` | `operator`, `admin` |

**Alert status transitions** (all others are rejected with `409 INVALID_TRANSITION`):
```
active ──acknowledge──▶ acknowledged
active | acknowledged ──close──▶ resolved | false_alarm                       (any type)
active | acknowledged ──close──▶ authorised_pickup | confirmed_theft          (possible_theft only)
```
`active` and `acknowledged` are "open". All other statuses are "closed".

## 3. DetectionEvent (cv → api)
Sent as `multipart/form-data` to `POST /api/ingest/events` with the fields `event` (JSON below) and `snapshot` (JPEG, max 2 MB).
```json
{
  "schema_version": 1,
  "event_id": "evt_01JD2X…",
  "type": "possible_theft",
  "run_id": "run_01JD2W…",
  "camera_id": "cam_01JD2V…",
  "source": "real",
  "occurred_at": "2026-11-22T14:47:05Z",
  "video_ts_s": 125.4,
  "bag": { "track_id": 18, "class": "handbag", "bbox": [812, 440, 905, 560] },
  "owner_track_id": 2,
  "carrier_track_id": 12,
  "separation_s": null,
  "owner_distance_m": 3.1,
  "owner_away_s": 35.0,
  "confidence": 0.94,
  "owner_match": 0.18
}
```
| Field | Rule |
|---|---|
| `owner_track_id` | nullable: unknown owner |
| `carrier_track_id`, `owner_away_s`, `owner_match` | **required** for `possible_theft`; must be `null` for `abandoned_bag` |
| `separation_s` | **required** for `abandoned_bag`; must be `null` for `possible_theft` |
| `owner_distance_m` | nullable: estimate, may be pixel-derived |
| `confidence`, `owner_match` | 0–1 |
| `is_demo` | **not sent**. The API derives it as `source == "mock"` (D-06) |

Response `201 {"alert_id": "alt_…", "duplicate": false}`. A resent `event_id` returns `200` with `duplicate: true` and creates nothing.

## 4. Run telemetry (cv → api)
All ingest routes need the `X-Worker-Key` header. A missing or wrong key is `401 UNAUTHORIZED`.

- `POST /api/ingest/runs` (**IngestRunCreate**, used by the standalone CLI): `{"camera": "CAM 01", "source": "mock", "video_path": "office_01.mp4"}`. `camera` is the camera **name** (names are unique). `video_path` is relative to `DATA_DIR/videos`: no `..`, no leading `/` or `\`, no drive letter, at most 255 characters, stored with `/`. Its existence is not checked here. Response `201 Run`, created as `running` with `started_at` set, `is_demo = (source == "mock")`. An unknown camera is `404 NOT_FOUND`, an inactive one `422 VALIDATION_ERROR`.
- `POST /api/ingest/runs/{run_id}/status`: `{"status": "running", "frames_processed": 3120, "fps": 14.2, "message": null}`. A worker may post `running`, `completed`, `stopped` or `failed` only (never `queued`). `frames_processed >= 0`, `fps >= 0`; both are totals and overwrite the stored values. Response `200 Run`.
- `POST /api/ingest/runs/{run_id}/frame`: multipart `frame` (JPEG, at most 2 MB, latest annotated frame, at most 1 per second). It overwrites the previous frame. Response `204`.

**Run status moves** (`RUN_TRANSITIONS`, checked with `can_update_run`):
```
queued  ──▶ running | stopped | failed
running ──▶ running (heartbeat) | completed | stopped | failed
completed, stopped, failed: terminal
```
A status post, frame or event for a run that cannot take it is `409 RUN_NOT_RUNNING` (events and frames need `running`). The first `running` sets `started_at` if it is empty; a terminal status sets `ended_at`. An unknown run is `404 NOT_FOUND`.

**Event checks** (`POST /api/ingest/events`), in this order: the `event` field parses as a `DetectionEvent` (else `422`); a known `event_id` returns `200 {duplicate: true}` with the first alert's ID, whatever the run's state now; the run exists (`404`) and is `running` (`409`); `camera_id` and `source` equal the run's (`422`); the `snapshot` is a JPEG (starts `FF D8 FF`) of at most 2 MB (`422`).

## 5. API read models (api → web)
**Alert**
```json
{
  "id": "alt_…", "ref_code": "SEC-2026-004-T", "type": "possible_theft", "status": "active",
  "is_demo": false,
  "camera": { "id": "cam_…", "name": "CAM 03", "location": "Student Affairs Office" },
  "run_id": "run_…", "event_id": "evt_…",
  "occurred_at": "…", "video_ts_s": 125.4,
  "bag": { "track_id": 18, "class": "handbag", "bbox": [812, 440, 905, 560] },
  "owner_track_id": 2, "carrier_track_id": 12,
  "separation_s": null, "owner_distance_m": 3.1, "owner_away_s": 35.0,
  "confidence": 0.94, "owner_match": 0.18,
  "snapshot_url": "/api/alerts/alt_…/snapshot",
  "next_statuses": ["acknowledged", "resolved", "false_alarm", "authorised_pickup", "confirmed_theft"],
  "acknowledged_by": null, "acknowledged_at": null, "closed_at": null,
  "created_at": "…"
}
```
`acknowledged_by` is `{id, display_name}` or `null`.
`next_statuses` lists the statuses this alert can move to now, worked out by the API from the transition table (§2) for its type and status, in a fixed order: `acknowledged`, `resolved`, `false_alarm`, `authorised_pickup`, `confirmed_theft`. It is empty for a closed alert. The web app offers exactly these actions and keeps no copy of the rules.

**Alert actions** (user token needed): `POST /api/alerts/{id}/acknowledge` (no body) and `POST /api/alerts/{id}/close` (`CloseRequest`, §6) both return the updated `Alert`. A move the table does not allow is `409 INVALID_TRANSITION`; a body that fails validation is `422`; an unknown ID is `404`. Every action writes one `AlertAction` in the same transaction. Closed alerts cannot be reopened (decided in Phase 7).

**AlertAction**: `{ "id": "act_…", "alert_id": "alt_…", "action": "acknowledge|close", "from_status": "active", "to_status": "acknowledged", "user": {"id","display_name"}, "note": null, "at": "…" }`

**Run**: `{ "id", "camera_id", "source", "video_path", "status", "is_demo", "frames_processed", "fps", "started_at", "ended_at", "message" }`. `video_path` is the file name relative to `DATA_DIR/videos` (e.g. `office_01.mp4`), never an absolute path.

**Camera**: `{ "id", "name", "location", "is_active" }`

**User (me)**: `{ "id", "username", "display_name", "role" }`

**Stats** (dashboard, `GET /api/stats`): `{ "open_total", "active", "acknowledged", "today_abandoned", "today_theft", "closed_today", "running_runs", "latest_alert" }`
- "Today" runs from midnight to midnight in the API's `campus_timezone` (default `Asia/Karachi`). `today_abandoned` and `today_theft` count alerts by `occurred_at`; `closed_today` counts by `closed_at`. `open_total`, `active` and `acknowledged` count every open alert, whatever its date. Demo alerts are counted.
- `latest_alert` is the alert the API stored last (`created_at desc, id desc`; not `occurred_at`, because events from recorded footage can carry an older time) as `{ "id": "alt_…", "ref_code": "SEC-2026-012-T", "type": "possible_theft", "camera_name": "CAM 03" }`, or `null` when there is none. The web app shows a new-alert toast when its `id` changes (added in Phase 8).

**HistoryStats** (History tiles, `GET /api/stats/history?days=1|7|30&type=`): `{ "total": 14, "false_alarms": 3, "avg_response_s": 130.0 }`. These count **closed** alerts whose `occurred_at` is in the last `days` days (default 7), optionally of one `type`. **Response** is the time from `created_at` to the first operator action: `acknowledged_at`, or `closed_at` for an alert closed straight from `active`. `avg_response_s` is their mean in seconds, or `null` when no alert is in the range (added in Phase 8).

## 6. Common API shapes
- **Page:** `{ "items": [...], "total": 42, "page": 1, "page_size": 20 }`
- **Error:** `{ "error": { "code": "INVALID_TRANSITION", "message": "Human-readable text." } }`. No stack traces and no file paths.
- **Error codes:** `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `VALIDATION_ERROR`, `INVALID_TRANSITION`, `DUPLICATE_EVENT` (reserved: a resent event is answered `200 {duplicate: true}`, not an error), `RUN_NOT_RUNNING` (HTTP 409, ingest to a run that cannot take it, §4), `RATE_LIMITED` (HTTP 429, with a `Retry-After` header in seconds; sent by `POST /api/auth/login` when one client address makes too many attempts), `INTERNAL_ERROR`.
- **Close request:** `{ "outcome": "false_alarm", "note": "Owner returned" }`. `outcome` is one of the four closed statuses (`resolved`, `false_alarm`, `authorised_pickup`, `confirmed_theft`). `note` is optional, at most 500 characters. Whether an outcome is allowed for the alert's type is decided by the transition table (§2), not by this model.

## 7. `config.json` (cv worker)
```json
{
  "classes": ["person", "handbag", "backpack"],
  "detector": { "weights": "yolo26n.pt", "conf": 0.35, "imgsz": 960, "device": "auto" },
  "tracker": { "type": "bytetrack", "track_buffer": 60 },
  "association": { "near_ratio": 1.0, "min_frames": 30 },
  "abandon": { "away_ratio": 2.5, "threshold_s": 60 },
  "theft": { "min_displacement_ratio": 1.5, "min_frames": 15, "owner_match_threshold": 0.6 },
  "output": { "annotated_video": true, "events_csv": true, "frame_push_interval_s": 1.0 },
  "api": { "base_url": "http://localhost:8000", "api_key_env": "NIGEHBAN_WORKER_KEY" }
}
```
Distance ratios are relative to the person's box height, so they adjust for perspective. Unknown keys cause an error, and missing keys fall back to the defaults shown.
