# Phase 03: Database schema, migrations, seed
Branch: `feature/phase-03-database` · Status: done (awaiting team review/merge) · Owner: Farooq khan

## Goal
Create the PostgreSQL tables from [Backend.md §4](../Backend.md) with SQLAlchemy 2 models and the first Alembic migration, an idempotent dev seed (users, cameras, demo alerts), and `GET /api/health`. No auth, no alert routes, no ingest yet.

## Decisions taken while planning
| # | Unclear point | Decision |
|---|---|---|
| 1 | Primary key type | `varchar(30)` holding the contract ID (`usr_<ULID>` etc.), made in Python with `nigehban_contracts.new_id`. A check constraint enforces the prefix and ULID pattern per table. No integer keys, so the API never translates IDs. |
| 2 | Enum storage | `varchar` + named check constraint whose value list is built from the contracts enums (`AlertStatus`, `EventType`, ...), so the DB and contracts cannot drift silently (a test compares them). |
| 3 | Type-conditional alert fields (Data-Contracts §3) | Also enforced in the DB: `abandoned_bag` needs `separation_s` and null `carrier_track_id`/`owner_away_s`/`owner_match`; `possible_theft` the reverse. `authorised_pickup`/`confirmed_theft` only on `possible_theft`. `closed_at` is set exactly when the status is closed; `acknowledged` status needs `acknowledged_at` + `acknowledged_by`. Ranges: `confidence`, `owner_match` in 0-1, `video_ts_s >= 0`, `bag_bbox` a 4-item JSON array. |
| 4 | `is_demo` (D-06) | `runs`: check `is_demo = (source = 'mock')`. `alerts` copies `is_demo` from its run (the service does it; a cross-table check isn't possible in a check constraint). |
| 5 | `alerts.run_id` nullable? | `NOT NULL`. Every alert comes from a run, so the seed creates one completed `mock` demo run per camera. |
| 6 | Foreign-key delete rule | `RESTRICT` everywhere. Alerts and their audit trail are never deleted by the app. |
| 7 | Extra indexes beyond Backend §4 | Foreign-key lookups: `alerts(camera_id)`, `runs(camera_id)`, `alert_actions(alert_id, at)`. Uniques: `users.username`, `cameras.name`, `alerts.ref_code`, `alerts.event_id`. |
| 8 | Timestamps | `timestamptz`, `created_at` defaults to `now()` in the DB. |
| 9 | `ref_code` sequence | `app/services/ref_codes.py`: next number = highest number used in that year + 1 (reusing `format_ref_code`). The unique constraint is the safety net. Making it safe under concurrent ingest (lock or retry) is Phase 6. |
| 10 | Seed idempotency | Natural keys: users by `username`, cameras by `name`. Demo runs and alerts get **deterministic** IDs (ULID bytes from a SHA-256 of a fixed key), so a rerun finds them and inserts nothing. Existing rows are never overwritten (a changed password survives a reseed). |
| 11 | Seed content | Users `operator/operator123` (operator) and `admin/admin123` (admin), dev only. Cameras CAM 01-04 with the prototype names (Main Gate Corridor, Library Entrance, Cafeteria Hall, Admin Block Lobby). 8 demo alerts modelled on the prototype, times relative to the first seed run, in several statuses; each non-active alert gets matching `alert_actions` rows, checked with `can_transition`. |
| 12 | Placeholder snapshots | One committed JPEG labelled "DEMO DATA" (`app/seed/assets/placeholder_snapshot.jpg`), copied to `DATA_DIR/snapshots/{run_id}/{event_id}.jpg`. `snapshot_path` stores the path **relative to `DATA_DIR`** (never absolute, never returned to clients). |
| 13 | Settings and paths | `app/core/settings.py` (pydantic-settings) reads the repo-root `.env`; real env vars win. Relative `DATA_DIR`/`CV_CONFIG` resolve against `apps/api`, not the working directory. `JWT_SECRET`, `WORKER_KEY` are `SecretStr`. Unknown keys (e.g. `DB_PORT`) are ignored. |
| 14 | Health shape | API-only schema (`app/schemas/health.py`), not a contract: `200 {"status":"ok","database":"connected"}`, or `503 {"status":"degraded","database":"disconnected"}` when `SELECT 1` fails (3 s connect timeout). No error text is returned. |
| 15 | Password hashing in the seed | `app/core/security.py` gets `hash_password`/`verify_password` (argon2) now; Phase 4 adds JWT there. |
| 16 | Test database | `nigehban_test` on the same server, created by the test fixture if missing; URL = `DATABASE_URL` with the DB name swapped, or `TEST_DATABASE_URL`. Tests run the real migration, and truncate tables between tests. Tests skip with a clear message if Postgres is down. |

## Plan
1. `app/core/settings.py`, `app/core/security.py` (hashing only).
2. `app/db/base.py` (Base + naming convention), `app/db/session.py` (engine, `SessionLocal`, `get_db`), `app/db/checks.py` (helpers building check SQL from enums/ID prefixes).
3. `app/models/{user,camera,run,alert,alert_action}.py`, re-exported in `app/models/__init__.py`.
4. `alembic.ini`, `alembic/env.py` (URL from settings unless the caller sets one), first revision `0001_initial_schema` (autogenerated, then reviewed).
5. `app/services/ref_codes.py`.
6. `app/seed/{data.py,runner.py,assets/placeholder_snapshot.jpg}` + thin `scripts/seed.py`.
7. `app/schemas/health.py`, `app/routers/health.py`, `app/main.py` (app factory, CORS for localhost:5173).
8. Tests in `apps/api/tests/`: settings, migration round trip, schema vs Backend §4, check constraints, ref codes, seed twice, health up/down.
